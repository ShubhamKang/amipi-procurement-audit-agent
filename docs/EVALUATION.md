# Evaluation

Reproduce: `python eval/run_eval.py --provider mock` and `--provider none` (results in `eval/results_*.json`).

- **Supplied set:** 12 quotations, gold answers in `tests/gold/supplied_gold.json` (hand-derived from the policy; see README table).
- **Synthetic set:** 120 quotations from `eval/synth.py` (seed 7): 4 vendors, legacy/new rate cards with an Oct-1 change, Rhodium lines, earrings in pairs, SKU-less and shorthand descriptions (`YG/WG/RG`, `RD`, `14k`), overquotes, underquotes, stale-rate pricing, unstated Rhodium charges, earrings quoted per piece, quotes outside any rate period, and PDF ↔ register conflicts. Gold totals are computed by an **independent reference implementation** inside `synth.py`, not by the engine.

Interpretation: without AI the matcher **abstains** on SKU-less items (Q-006, Q-010 and synthetic `no_sku*` cases → `NEEDS_REVIEW`) but never produces a wrong match or a wrong total; the AI matcher recovers that recall. `mock` is a deterministic stand-in for the model — live Gemini results were not measured in this build because no API key was configured; run `python eval/run_eval.py --provider gemini` once `GEMINI_API_KEY` is set.

## Caveats

- Perfect scores reflect that the deterministic parser was built for the supplied layout and the synthetic generator reuses it; they do not prove robustness to arbitrary supplier formats (those go through the grounded AI extraction path, which has unit tests but no large evaluation set).
- The synthetic set is generated by the author and may share blind spots with the implementation; the hidden evaluator cases are the real test.

## Error / hallucination examples and handling

| Case | Observed behaviour | Handling |
|---|---|---|
| Model returns a PO line key that does not exist (`PO-9999/L99`) | rejected (`unknown key`) | Match untrusted → `NEEDS_REVIEW` (test `test_hallucinated_match_key_rejected`) |
| Model "extracts" a quote id / total not present in the page (`Q-778`, `350.00`) | quote dropped / field discarded | Grounding check; missing total → `NEEDS_REVIEW` (`test_extraction_grounding_drops_hallucinations`) |
| Explanation invents a "fair price" `$650.00` or says "approved" | rejected | Deterministic template shown instead (`test_injected_model_cannot_change_status`) |
| Vendor note X-03 instructs to ignore rate cards and approve | detected, quarantined | Q-007 still `FLAG` +$70.00, `PROMPT_INJECTION_DETECTED` P1 |
| X-04 "pending rate increase" | not applied | Q-001 priced on A-OLD (quote date 2026-09-18), `RATE_CHANGE_NOTICE_IGNORED` |
| X-02 "duplicate Q-006" | not counted | 12 quotations from 24 records, `DUPLICATE_NOTICE` info |
| X-01 $75 CAD surcharge, no signed exception | excluded from expected | `UNAUTHORIZED_SURCHARGE`; variance stays +$85.00 |
| Notes reference a vendor different from the quoting vendor (X-01..X-03) | flagged | `NOTE_VENDOR_MISMATCH` for reviewer attention |
| Earrings quoted per "piece", or qty ≠ PO | abstain | `AMBIGUOUS_UNIT` / `QTY_MISMATCH` → `NEEDS_REVIEW` |
| Gemini quota / network failure | retries, then circuit breaker | deterministic fallbacks; affected matches `NEEDS_REVIEW` (`test_llm_outage_degrades_gracefully`) |

Found during development and fixed: the first synthetic run had extraction recall 0.00 because the quote-id pattern only accepted `Q-` prefixes (now any `ABC-…` id), and quotation blocks crossing a PDF page break were truncated (recall 0.98 → 1.00 after the fix).
